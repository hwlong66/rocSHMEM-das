# GDA 代理集合通信

本文说明 GDA 自研集合通信的代码组织、代理路由和执行约束。
集合算法位于 `../collectives/`；本目录提供候选管理、路由规划、同步协议和代理传输辅助。

## 配置与术语

`ROCSHMEM_DISABLE_PXN` 控制是否启用 PXN：

| 取值 | 行为 |
| --- | --- |
| `1`（默认） | 保留原有非 PXN 路径，不要求通信两端使用同名 NIC。 |
| `0` | 跨 IPC domain 传输使用兼容 NIC 代理（默认同名，配置后按平面）；不允许失败后回退到不受限制的跨域路径。 |

可选配置 `ROCSHMEM_NET_PLANE="shca_0,shca_3|shca_1,shca_2"`：逗号分隔同一平面的 NIC，`|` 分隔平面。
PXN 开启时，同平面 NIC 允许跨节点配对；未列出的 NIC 不参与跨域代理选路。
未设置该变量时保持同名配对；PXN 关闭时忽略平面配置并打印提示。
配置者必须保证同平面内实际网络可达，该配置不探测连通性，也不重新选择 GDA 网卡。

本文中的“NIC 组”指同一个互通通信平面中的 NIC 集合：配置平面时按配置分组；
未配置时，默认将各节点的同名 NIC 视为一组。组内可配对是选路规则，实际互通由部署配置保证。

初始化会规范化并交换配置。空字符串、空组、重复 NIC、不同 PE 配置不一致均报错。
每个 PE 当前须只选择一张 NIC；多 NIC/PE 缺少明确 NIC→QP 映射时，平面模式提前报错。
WORLD 同步在每个 IPC domain 内按当前 NIC 规则选择固定代理，不要求代理是域首 PE；
部分 team 则在各参与域的 team 成员中选取固定代理，其 NIC 必须属于同一组。

- **PE**：参加通信的进程。
- **IPC domain**：同一物理节点内能够通过 IPC 直接互通的一组 PE。一个节点可以包含多个 IPC domain。
- **代理 PE**：通过自身选定的 NIC，代表域内其他成员进行网络传输。
- **WORLD**：包含全部 PE 的 team；部分 team 仅包含其中一部分成员。

`ipc_domain_first_pe` 是 IPC domain 首个成员的 world PE，不是物理节点编号。
PXN 复用 GDA 已完成的 GPU–NIC 选择，不重新选择网卡。

## 代码组织

| 位置 | 职责 |
| --- | --- |
| `../context_gda_tmpl_device.hpp` | 社区接口实现及自研入口接入点。 |
| `../context_gda_tmpl_device_das.hpp` | 集合实现头文件的包含入口，以及两种模式共用的 QP 辅助。 |
| `../collectives/` | 自研集合入口、路径分派、数据组织、工作区和同步阶段管理。 |
| `candidate_host.hpp` | 代理 NIC 候选的构建与交换。 |
| `network_plane.hpp` | 人工网络平面解析、规范化和 Host NIC 兼容判断。 |
| `layout_host.hpp` | Host 侧 WORLD/team 代理布局构建、校验和路由状态。 |
| `route_device.hpp` | 设备侧能力检查、代理选择和路由计划构建。 |
| `entry_device.hpp` | 统一代理尝试入口及失败后的回退限制。 |
| `sync_device.hpp` | 域内汇聚、跨域同步、域内释放及线程作用域适配。 |
| `transfer_device.hpp` | 代理 GET/PUT 的共用调用边界。 |

集合入口直接定义在对应的集合文件中，不再增加独立的 dispatch 转发层。
`_das` 表示自研入口；模式专属实现以 `_pxn` 或 `_nopxn` 标识。

## 初始化与执行流程

1. `GDABackend::select_nics()` 选择各 PE 实际使用的 NIC。
2. `setup_proxy_candidates()` 收集代理候选，建立 PE、NIC 名称及 IPC domain 映射。
3. `setup_pxn_sync_routes()` 为 PXN 建立固定同步路由。
4. 创建 team 时，`setup_team_proxy_routes()` 检查成员内可用的代理布局。
5. 集合入口调用 `internal_try_collective_pxn()`，执行适用的 PXN 算法并统一处理失败策略。
6. 集合算法准备数据路由计划，通过代理传输，并在完成后推进相应状态。

初始化的代理元信息（NIC 候选数量、平面配置长度和解析状态）搭载已有 heap-rkey
allGather；IPC domain 确定后，候选记录与规范化平面字符串只新增一次 allGather。
PXN 关闭时不执行该内容交换；启用状态、解析错误及配置长度不一致在元信息阶段统一检查。

`SelectProxyCollectiveLayout()` 描述可用的路由能力，不直接代表具体集合算法。
WORLD 对齐能力是优化条件；部分 team 则需要满足成员范围和域内代理约束。

## 同步路由与数据路由

同步代理在初始化或 team 创建时确定，用于稳定的阶段握手。
`BuildFixedDomainProxyLayout()` 为各域构建固定代理布局，供同步及缺少映射时的数据路由回退使用，
不生成设备侧动态数据轮询的候选列表。
数据代理按任务约束和操作序号选择，WORLD 与部分 team 共用选择规则：

1. 筛选满足源、目标及 team 成员约束的候选。
2. 先按任务约束轮询可配对的 NIC，再在对应 NIC 内轮询代理 PE。
3. 准备路由计划，供本次操作的各阶段复用。

PXN 要求通信两端 NIC 满足当前同名或同平面规则。部分 team 的代理必须属于该 team。
固定目标、块所有者等算法约束优先于轮询，避免为负载均衡增加不必要的中转。

数据轮询使用独立的 `proxy_data_route_sequence`，不使用同步 epoch 代替。
同步 epoch 区分协议阶段；路由序号决定候选轮次，两者由参与成员一致推进。
并发操作通过独立 team 隔离工作区、同步槽及路由状态。

初始化日志中的候选映射和固定同步代理不代表每次操作实际选择的数据路由。
候选日志保留已发现的 NIC，并用 `policy allows` 明确当前同名或平面规则是否允许它参与选路；
未列入平面的 NIC 标为 `no`。`compatible NIC in all IPC domains` 表示各参与域都有同组 NIC，
不要求名称相同，也不代表已满足具体任务的全部约束。

## 集合算法

| 操作 | PXN 执行方式 |
| --- | --- |
| sync / barrier | 域内汇聚，由固定代理跨域同步，再在域内释放。 |
| broadcast | 源代理准备数据、代理间 PUT、目标域 IPC 分发；WORLD 与部分 team 共用协议。 |
| fcollect | 域内打包后广播至最终输出；根据工作区容量合并或按成员分批。 |
| alltoall | 完整 WORLD 映射使用目标定向传输；其他支持的布局使用行传输流程。 |
| alltoallv | 全体一致确认等长连续布局后复用 alltoall；否则交换计数信息并传输打包行。 |
| allreduce / reduce-scatter | 共用分段归约框架：域内归约、根域合并、结果返回；输出范围按操作区分。 |

集合算法保留各自的数据排列、分块和工作区协议，路由层仅为已有任务分配代理。
非 PXN 保留原有广播、收集、交换和归约实现，不进入新增的数据代理轮询。

## 支持边界

- broadcast、fcollect、alltoall、allreduce、reduce-scatter 及 team sync/barrier 支持具备合法代理路由的跨 IPC domain 部分 team。
- PXN alltoallv 当前仅支持 WORLD 成员布局；range sync 的 PXN 接入也仅覆盖 WORLD 范围。
- 部分 team 必须在参与的每个 IPC domain 内找到符合当前同名或同平面规则的成员代理；
  当前不提供 team 外代理推进机制。
- 多 NIC/PE 配置必须具备明确的 NIC 到 QP 映射，不能仅凭网卡名称推断 QP 归属。
- 对齐快路径依赖完整连续的 IPC domain 和有效同步布局；
  候选路由存在不表示所有算法均满足执行条件。
- PXN 失败后的普通路径仅限允许的域内处理，不能进入不受限制的跨域传输。

## 设备侧代理选择边界

- `SelectProxyDataRoute()` 是统一的单路由选择入口：按合法 NIC 对轮询，再在对应 NIC 内轮询代理 PE。
  固定目标时，在该入口内计入目标在兼容成员中的序号；WORLD 与部分 team 使用相同规则。
- `BuildProxyDataRouteLanes()` 从公共选择器构建端点互不冲突的并行通道，
  broadcast 仅提供成员范围、已有操作编号和通道容量。
- alltoall 按实际源代理的暂存冲突分批；批次及数据块大小使用本次操作编号计算。
- `BuildProxyDomainLanes()` 为 fcollect、allreduce 和 reduce-scatter 统一规划每域负责人：
  每条通道先选一个所有参与域都有可用代理的 NIC 组，再在各域按 NIC、PE 轮询，并排除已使用端点。
  fcollect 请求一个通道；归约请求多个端点互不重复的通道。
- 单路由、并行路由和每域负责人规划共用成员过滤、兼容判断及端点计数/选择函数。
  源—目标路由只要求两端 NIC 可配对；各域负责人规划要求所有参与域选出的 NIC 属于同一组。
  两种模式均先筛选仍有可用代理的 NIC 对或 NIC 组，再执行轮询，不让不可用候选占据轮次。
- 映射缺失时保留 Host 已验证的固定路由；有映射但无法满足 NIC 配对或各域负责人约束时则报错，不放宽兼容条件。

- 固定代理通过 `GetValidatedDomainProxy()` 读取，WORLD 与部分 team 共用该接口；它不执行动态选择。

- 源—目标代理通道和各域代理负责人规划均在候选过滤时排除已使用端点，再按剩余可用候选轮询；不再选中冲突路由后重试。

## 规划缓存与复用

未配置平面和配置平面共用以下缓存机制，仅兼容规则及合法候选内容不同。
缓存按本次规划、操作或数据块构建，不跨不同成员范围或配置复用旧结果。

- **源—目标代理通道的端点计数**：通道连接一个源代理 PE 和一个目标代理 PE。
  在单次规划开始时统计各 NIC 的可用端点数，每分配一对代理即递减相应计数。
  该缓存不跨规划调用保存，成员范围、固定端点或排除集合变化后重新统计。

- **合法 NIC 对位图**：全局去重后的 NIC 名称数 ≤64 时，单次通道规划使用位图缓存合法 NIC 对；
  超过 64 时使用通用遍历，功能不受此位图范围限制。
  每次仅遍历两端仍有可用代理的合法 NIC 对，保持原有 NIC 顺序和轮询结果。

- **WORLD alltoall 计划**：每个工作组（WG）构建一份计划，供可用性检查、暂存批次、分块容量及传输共同使用。
  每个有向目标只选择一次源代理，批次通过代理负载计数递增生成。

- **各域代理负责人规划**：每条通道在各参与 IPC domain 中各选一个代理负责人，
  这些负责人的 NIC 必须属于同一 NIC 组。它描述一组负责人，实际数据仍在两个 PE 之间传输。
  单次规划内缓存 NIC 分组、域边界和剩余计数，并逐通道扣减；
  仅在域数与 NIC 名称数的乘积不超过缓存预算时启用，超出时使用通用查询路径。

- **集合成员区间**：fcollect 在每次操作开始时缓存各域成员区间和广播阶段数；
  归约复用本域成员区间。

- **wave 广播路由**：使用各 lane 的私有寄存器分布保存路由，通过 wave shuffle 共享。
  仅在当前数据块的各阶段复用，数据块之间继续按原轮询轮次重新规划。

## 代理容量限制

容量常量集中定义在 `src/constants.hpp`，与同步槽容量分别管理。

| 常量 | 默认值 | 用途 |
| --- | --- | --- |
| `ROCSHMEM_PROXY_MAX_PES` | 256 | 按 WORLD PE 编号索引的代理映射和计划表容量。 |
| `ROCSHMEM_PROXY_MAX_IPC_DOMAINS` | 256 | IPC domain 映射和域计划表容量。 |
| `ROCSHMEM_PROXY_MAX_NIC_NAMES` | 256 | 全局去重后的 NIC 名称及端点计数表容量。 |
| `ROCSHMEM_PROXY_PLAN_CAPACITY` | 256 | 工作组内各域代理负责人计划的条目总容量。 |
| `ROCSHMEM_PROXY_DOMAIN_CACHE_CAPACITY` | 256 | 多域规划缓存的条目预算，要求域数 × NIC 名称数不超过该值。 |
| `ROCSHMEM_PROXY_NIC_MASK_BITS` | 64 | 单字位图可覆盖的 NIC 名称数；超过时使用通用遍历。 |

缓存预算不足会使用通用查询路径；映射或计划表容量则是对应数据结构的实际边界，
不能将所有容量限制都视为可回退的缓存预算。
这些限制不替代 pSync 的分配和寻址限制，仅调大代理容量常量不能保证支持更大 PE 规模。
