这个目录集中管理 GDA 集合通信的代理选路、同步和数据搬运。跨节点时，由代理 PE 使用网卡传输，节点内的其他 PE 通过 IPC 交换数据。这里既有传统代理路径，也有 PXN 路径；它们按职责共享代码，不按开关各维护一套算法。

## PXN 与传统代理的区别

- `ROCSHMEM_DISABLE_PXN=1`（默认）：不要求两端网卡同名。符合代理算法条件时使用代理，否则保留原 GDA 路径。
- `ROCSHMEM_DISABLE_PXN=0`：跨节点传输必须使用同名网卡代理。先检查候选网卡、团队布局和同步路由，再选择集合算法；不能因为代理路径不适用就回退到可能不互通的普通跨节点路径。

PXN 复用 GDA 已选中的 GPU–NIC 结果，不重新选择网卡。`ipc_domain_first_pe` 表示一个 IPC 互通域的首个 world PE，不是硬件节点编号。Host 侧规划的候选通道与同步路由也不等于设备侧实际使用的每条数据通道。

IPC domain 表示同一物理节点内可直接通过 IPC 互通的一组 PE；一个物理节点可以包含多个 IPC domain。

## 从初始化到通信

1. `GDABackend::select_nics()` 为各 PE 选择实际使用的网卡；PXN 基于这些结果收集代理候选，不重新选择网卡。
2. `GDABackend::setup_proxy_routes()` 按同名网卡建立跨 IPC 互通域的候选路由并检查 WORLD 布局；创建部分 team 时再检查其成员能否组成代理路由。同步路由是固定通道，数据通道可由设备按操作和消息选择。
3. 设备侧的 `SelectProxyCollectiveLayout()` 判断可用布局；集合操作再通过 PXN 专用的 `internal_try_pxn_proxy_*()` 或共用代理入口选择算法。PXN 集合入口使用 `internal_try_pxn_collective()` 防止失败后落入不安全的跨节点路径。代理 PE 负责跨节点传输，其他 PE 通过 IPC 参与。

## 集合操作如何使用代理

- `sync` / `barrier`：在 IPC 互通域内汇聚，再由代理执行跨节点同步。
- `broadcast` / `fcollect`：按 team 和 WORLD 布局选择单代理或多代理传输，再在节点内分发。
- `alltoall`：根据数据布局选择对齐或路由路径。
- `alltoallv`：PXN WORLD 先在 IPC 互通域内汇总规则布局标志与计数，再跨区域一致确认。全体计数相同且位移连续时复用 alltoall 代理算法；否则按发送 PE 打包整行，广播一次计数表，再分块传输，各接收 PE 保存自己的片段。计数表与数据接收块分开保存，避免缓冲复用改变循环边界。仅当计数表无法放入工作区时保留逐 PE 对广播。PXN 关闭时保留原来的规则布局及 COPY/GET 分发。
- `allreduce` / `reduce-scatter`：先完成节点内归约或分段，再通过代理交换数据；部分布局使用广播式正确性路径。

WORLD 小消息 fcollect 会先打包节点内贡献，再按节点广播；每节点打包数据超过 64 KiB 时保留原有路径。
WORLD 的广播式归约先在节点内合并贡献，再交换节点级结果。对齐 allreduce 继续使用分段并行路径。
部分 team 的单 PE 输出达到 256 KiB、且参与成员数多于 IPC 互通域数时，也使用节点归约：
由选中的 team 代理直接读取本地成员的 IPC 输入，再广播节点结果；非原地小消息保留逐 PE 广播。
`dest == source` 时不受该消息门限限制：必须先保存本节点的输入，再更新结果，
即使一个节点只有一个 team 成员也一样，避免后续广播读到已累加的结果。

这些操作共享选路信息，但数据排列、缓冲区和同步步骤不同，因此不强行合成一个集合算法。

## 文件分工

| 文件 | 职责 |
| --- | --- |
| `candidate.hpp` | 收集、交换已选网卡对应的代理 PE 候选。 |
| `route_plan_host.hpp` | Host 侧同名网卡选路与路由状态。 |
| `layout.hpp` | 检查 WORLD 和部分 team 是否具备所需的代理布局。 |
| `route_device.hpp` | 设备侧资格判断、代理 PE 与数据通道选择。 |
| `sync_device.hpp` | 代理同步，包括 IPC 互通域内汇聚与跨节点同步。 |
| `collective_device.hpp` | 按 broadcast/fcollect、all-to-all、reduction 分区实现集合算法。 |
| `entry_device.hpp` | 统一尝试 PXN 算法，并限制失败后的跨节点回退。 |

`_das` 文件负责把公开 API 的 team、线程范围和 onstream 分片参数接入这些实现。
类型化 API 与字节 API 应共用入口，避免一个接口已接入 PXN、另一个仍走旧路径。
wave 接口只同步参与的 wave，不能在内部使用要求整个 WG 参与的屏障。

代理函数在 `GDAContext` 中声明，集合算法实现在上述设备头文件。
WG 的代理读写共用 `internal_proxy_getmem_wg()` 和 `internal_proxy_putmem_wg()`，
实现在 `context_gda_device_coll_das.cpp`。调用方选择代理 PE 与 QP 行，
入口统一计算 QP 索引，复用 GDA 的 IPC/RDMA 选择和完成处理。
读取入口保留 `__noinline__` 的整 WG 设备函数边界；调整此边界后，
需要复测 2 WG × 128 线程混合序列和 fcollect，普通内联版本曾在该用例中触发 lkey 错误。

broadcast 的对齐多代理数据搬运和 allreduce 的分段归约已在两种模式间共用；reduce-scatter 使用共用分发入口，并在资格满足时共用环形实现。是否允许执行以及同步协议仍依模式选择。

## 当前限制

- 部分 team 必须在每个参与的 IPC 互通域内找到 team 成员作为同名网卡代理。否则需要额外的 team 外代理推进机制，目前不支持。
- 一个 PE 使用多张网卡时，不能只凭网卡名推断 QP 行对应哪张网卡；没有明确映射的多通道路径不会贸然启用。
- 对齐 WORLD 数据路径要求完整、连续的 IPC 互通域和可用的同步布局。某些路由可用不代表所有快路径均可用。
- 部分 team 的节点归约只在已有合法 team 代理路由时启用；其他布局仍需各自的资格检查，不能因为某个快路径通过就删除其余路径。

测试时应分别覆盖 PXN 开启和关闭、WORLD 与部分 team、小消息与大消息。当前特殊网络仅保证同名网卡互通，不能用它上面 PXN 关闭后的超时判断传统路径是否正确；传统路径需在网卡互通的环境回归。

## 回归脚本

节点容器的 build 目录中可用 `bash ../scripts/run_pxn_perf.sh <测试程序> <日志目录>`
运行带结果校验的双节点对比测试；`PXN_TEST_HOSTS`、`PXN_TEST_MAX_BYTES`、`PXN_TEST_LOOPS` 和
`PXN_TEST_WGS` 可调整节点、最大消息、迭代数和 workgroup 数。脚本要求显式设置 `PXN_TEST_HOSTS`、`PXN_TEST_PES` 和 `PXN_TEST_GPU_LIST`，不会默认占用整节点。
`PXN_TEST_PERMUTE_NICS=1` 仅用于指定 SHCA 拓扑、每节点完整 8 PE 的测试，交换第二节点的部分 NIC 映射；不要用于部分 GPU 配置。
显存紧张时可通过 `PXN_TEST_HEAP_BYTES` 和 `PXN_TEST_CONTEXTS` 减小测试堆和上下文数量；前后对比需使用相同配置。
`PXN_TEST_TIMEOUT_SECONDS` 可调整单项超时（默认 180 秒）；脚本失败时输出退出码和日志路径，`124` 表示达到超时上限，不代表数据校验失败。

`-a 20` 的不规则用例通过 `ROCSHMEM_TEST_ALLTOALLV_IRREGULAR` 选择：`1` 为按接收方变化的紧凑布局，
`2` 为按收发双方变化的计数及反向带间隔源位移，`3` 为与 on-stream 用例相同的发送方加权分布（按元素计数）。
`4` 检查 PE 0 本地规则但整体非对称的矩阵，`5` 检查一个 PE 完全无收发，`6` 检查整个矩阵为空。
不设置该变量则测试规则布局。每个 WG 使用独立 team 和显式缓冲区跨度；输入、元数据上传及结果取回均使用 HIP 拷贝，校验保持开启。
部分 GPU 调测应显式设置 `PXN_TEST_PES`、`PXN_TEST_HOSTS` 和 `PXN_TEST_GPU_LIST`，运行前确认资源已获准使用。`PXN_TEST_QPS_PER_PE` 配置每 PE 的默认 context QP 数（默认 1），不是总 QP 数。

`tests/unit/proxy_partial_alltoall_test.cpp` 默认运行 84 组正确性检查。
显式给每个 MPI 进程设置 `ROCSHMEM_TEST_PARTIAL_ALLTOALL_ITERS=10` 可开启专项计时：
每组先预热 2 次，再用 HIP event 测量 10 次内核调用，报告所有参与 PE 中最慢者的
平均延迟；双 WG 的数字是一对独立 team 操作的完成时间，不除以 WG 数。
计时包含内核启动及私有 context 创建/销毁，不包含 Host 数据拷贝或 MPI 归约。
每组计时后仍检查最终结果、输出边界和非成员缓冲区；它不代替逐次改变输入的默认回归，
也不代替 `-a 120` 的跨接口综合用例。对比版本应使用同一测试对象和相同资源配置。
